# Конфігурація

Yurst налаштовується через змінні середовища. Єдина обов'язкова змінна — `TOKEN`, всі інші мають значення за замовчуванням.

## Файл .env

Створіть файл `.env` у корені проєкту:

```dotenv title=".env"
# Обов'язково
TOKEN=b.your_bot_token_here

# Опціонально
MODE=ws
YURST=dev
LOG_FILE=bot.log
```

<Callout title="Безпека">
  Додайте `.env` до `.gitignore`, щоб не випадково не опублікувати токен у репозиторії.
</Callout>

### Завантаження змінних

Yurst автоматично читає `.env` під час імпорту. Підтримуються два способи:

**Рекомендований** — передача через Node.js:

```sh
node --env-file=.env src/index.js
```

**Автоматичний** — Yurst шукає `.env` у поточній робочій директорії, а якщо там його немає — у корені workspace. Додатково шлях можна задати змінною `YURST_ENV_FILE`.

Якщо змінна вже існує в `process.env`, значення з `.env` не перезапише її. Це дозволяє перевизначати конфігурацію через середовище.

## Змінні середовища

### Обов'язкові

| Змінна | Опис |
| --- | --- |
| `TOKEN` | Токен бота у форматі `b.xxxx`. Отримати можна в налаштуваннях бота на Yurba.one |

Якщо `TOKEN` не знайдено, Yurst виводить помилку та завершує процес:

```
Yurst: TOKEN not found. Create .env with TOKEN=b.xxxx
```

### Транспорт

| Змінна | За замовчуванням | Опис |
| --- | --- | --- |
| `MODE` | `ws` | Режим отримання оновлень: `ws` (WebSocket) або `poll` (long polling) |
| `WS_IDLE_MS` | `0` | Watchdog неактивності WebSocket у мілісекундах. `0` — вимкнено |
| `WS_MAX_FAILS` | `5` | Кількість коротких невдалих підключень до переходу на polling. `0` — без обмежень |
| `POLL_TIMEOUT_S` | `30` | Таймаут long polling на стороні сервера (секунди) |

### HTTP та API

| Змінна | За замовчуванням | Опис |
| --- | --- | --- |
| `API_TIMEOUT_MS` | `10000` | Таймаут HTTP-запитів до API (мілісекунди) |
| `MAX_TEXT` | `4000` | Максимальна довжина однієї частини повідомлення (символи) |

### Логування

| Змінна | За замовчуванням | Опис |
| --- | --- | --- |
| `YURST` | — | `dev` вмикає режим розробки з детальними логами |
| `YURST_LOG` | `info` | Мінімальний рівень логів: `debug`, `info`, `warn`, `error` |
| `LOG_FILE` | — | Шлях до файлу для запису логів (додається до stdout) |

### Інші

| Змінна | За замовчуванням | Опис |
| --- | --- | --- |
| `YURST_ENV_FILE` | — | Додатковий шлях до `.env`, який перевіряється першим |

## Режими транспорту

### WebSocket (рекомендовано)

```dotenv
MODE=ws
```

Переваги:
- Миттєве отримання оновлень
- Менше навантаження на API
- Автоматичний reconnect з exponential backoff

Якщо WebSocket недоступний (Node < 22 без пакету `ws`) або з'єднання падає `WS_MAX_FAILS` разів поспіль — Yurst автоматично переходить на polling.

### Long Polling

```dotenv
MODE=poll
```

Використовується коли:
- WebSocket недоступний у середовищі
- Потрібен повний контроль над запитами
- Налаштовано `MODE=poll` явно

Докладніше про роботу транспорту: [Транспорт оновлень](./transport).

## Режим розробки

Для локальної розробки увімкніть детальні логи:

```dotenv
YURST=dev
YURST_LOG=debug
```

У режимі `dev`:
- Логер виводить debug-повідомлення
- У логи потрапляють сирі оновлення (raw update)
- Показуються деталі HTTP-запитів

Приклад логів у dev-режимі:

```
[info]  bot start | MODE=ws | node=v22.0.0 | DEV
[info]  bot Ani @ani_ id=2251
[info]  bot commands → 200 /ping[all] /help[all]
[debug] api GET /bot/me → 200 (156ms) {User: {...}}
[info]  update #12345 via=ws lag=1s | message /ping
```

## Приклади конфігурації

### Продакшн

```dotenv
TOKEN=b.prod_token
MODE=ws
LOG_FILE=/var/log/bot.log
WS_MAX_FAILS=10
```

### Розробка

```dotenv
TOKEN=b.dev_token
MODE=ws
YURST=dev
YURST_LOG=debug
LOG_FILE=bot.log
```

### Тестування з polling

```dotenv
TOKEN=b.test_token
MODE=poll
YURST=dev
YURST_LOG=debug
POLL_TIMEOUT_S=10
```

## Об'єкт CFG

Після завантаження конфігурація доступна всередині пакета як заморожений об'єкт:

```js
// Внутрішня структура (не публічний експорт):
CFG = {
  mode: 'ws',           // 'ws' | 'poll'
  logFile: undefined,   // string | undefined
  wsIdleMs: 0,          // number
  wsMaxFails: 5,        // number
  maxText: 4000,        // number
  apiTimeoutMs: 10000,  // number
  pollTimeoutS: 30,     // number
};
```

<Callout title="Immutable">
  Об'єкт `CFG` заморожено через `Object.freeze()`. Змінити значення під час роботи неможливо — перезапустіть процес після зміни `.env`.
</Callout>

## Змінні середовища процесу

Ви можете передавати змінні безпосередньо процесу:

```sh
TOKEN=b.xxx MODE=poll YURST=dev node src/index.js
```

Або через CI/CD середовище — це безпечніше ніж зберігати токен у файлі.
