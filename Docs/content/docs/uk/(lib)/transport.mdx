# Транспорт оновлень

Yurst отримує оновлення від Yurba через WebSocket або long polling. Режим обирається змінною `MODE`.

## WebSocket

Режим за замовчуванням (`MODE=ws`).

### Вимоги

Yurst використовує глобальний `WebSocket` з Node.js 22+:

```js
// Node.js 22+: нативний WebSocket
globalThis.WebSocket // доступний

// Node.js < 22: потрібен пакет ws
import { WebSocket } from 'ws';
```

<Callout title="Пакет ws">
  `ws` не входить до залежностей Yurst. Для Node.js < 22:
  ```sh
  npm install ws
  ```
</Callout>

### Протокол

**Підключення:**

```
wss://api.yurba.one/ws?token=b.xxxx
```

**Привітання:**

Після відкриття сокета Yurba надсилає JSON:

```json
{
  "ok": 1,
  "version": "1.2.3"
}
```

**Оновлення:**

```json
{
  "Type": "update",
  "Message": { /* сире оновлення */ }
}
```

**Помилка автентифікації:**

```json
{
  "ok": 0,
  "error": "..."
}
```

Сокет закривається з кодом `3000`, процес завершується.

### Reconnect з exponential backoff

При розриві з'єднання:

1. Затримка від 1 до 30 секунд
2. Випадковий jitter до 25%
3. Подвійна затримка при кожній невдачі
4. Скидання лічильника після успішного з'єднання >10 секунд

```
[info]  ws connecting… (attempt 1)
[info]  ws socket open — waiting for greeting…
[info]  ws connected — server 1.2.3
...
[warn] ws closed — code=1006 lived=5m frames=1523
[info]  ws reconnecting in 2000ms…
```

### Fallback на polling

Коли кількість коротких невдалих з'єднань досягає `WS_MAX_FAILS`:

```
[warn] ws 5 failed connections in a row — falling back to polling
[info] poll long polling started
```

Налаштування:
- `WS_MAX_FAILS=5` — кількість спроб (0 = без обмежень)
- `WS_IDLE_MS=0` — watchdog неактивності (0 = вимкнено)

### Watchdog неактивності

Якщо `WS_IDLE_MS > 0`, сокет закривається при відсутності кадрів:

```dotenv
WS_IDLE_MS=30000  # 30 секунд без активності → reconnect
```

## Long Polling

```dotenv
MODE=poll
```

Або автоматично при недоступності WebSocket.

### Принцип роботи

1. Бот робить `GET /bot/updates?timeout=30`
2. Сервер тримає з'єднання до 30 секунд
3. При наявності оновлень — повертає масив
4. Бот обробляє і зсуває `offset`

### Offset

Після отримання пакету оновлень:

```js
offset = Math.max(offset, max(update.ID) + 1);
```

Це підтверджує обробку оновлень серверу.

### Повторні спроби

При помилках:

- Backoff від 1 до 30 секунд
- Для HTTP 429 — мінімум 5 секунд
- Для HTTP 401 — завершення процесу

```
[warn] poll request failed (503) — retrying in 2000ms
```

## Порівняння режимів

| Характеристика | WebSocket | Long Polling |
| --- | --- | --- |
| Затримка | Мінімальна | Залежить від `POLL_TIMEOUT_S` |
| Ресурси | Одне з'єднання | Періодичні HTTP-запити |
| Налаштування | `MODE=ws` | `MODE=poll` |
| Fallback | Автоматично на polling | Немає |
| Node.js | 22+ або пакет `ws` | Будь-яка версія |

## Дедуплікація оновлень

При reconnect WebSocket може повторно надіслати останні оновлення.

Yurst використовує LRU-кеш останніх ~1000 ID:

```js
if (seen.has(update.ID)) {
  stats.dupes++;
  return; // пропускаємо дубль
}
seen.add(update.ID);
```

## Паралельність обробки

Транспорт **не чекає** завершення обробника перед взяттям наступного оновлення.

```js
// Оновлення обробляються паралельно
bot.on('message', async (ctx) => {
  await new Promise(r => setTimeout(r, 5000));
  // За цей час могло прийти 10+ нових повідомлень
});
```

Всі активні Promise відстежуються через `inflight` Set для graceful shutdown.

<Callout>
  Якщо обробники ділять стан (Map, змінні), не припускайте послідовного виконання. Використовуйте черги або м'ютекси за потреби.
</Callout>

## Налаштування

### WebSocket

```dotenv
MODE=ws
WS_MAX_FAILS=5     # спроб до fallback
WS_IDLE_MS=0       # watchdog (0 = вимкнено)
```

### Polling

```dotenv
MODE=poll
POLL_TIMEOUT_S=30  # таймаут на сервері
```

### HTTP

```dotenv
API_TIMEOUT_MS=10000  # таймаут запитів
MAX_TEXT=4000         # макс. довжина повідомлення
```

## Діагностика

У dev-режимі (`YURST=dev`) транспорт логує деталі:

```
[debug] ws frame #1523 { ok: 1, version: "1.2.3" }
[debug] ws frame #1524 { Type: "update", Message: {...} }
[info]  update #12345 via=ws lag=1s | message /ping
```
